Unverified reporting, attributed to Wang Report: The attacker restored the files after running the credential stealer. According to Aikido’s research, reported by BleepingComputer, the attacker also deleted workflow runs and logs, completing the cleanup in under a minute.

Unverified reporting, attributed to Wang Report: The repository owner could find the expected code. The execution record could already be gone.

Unverified reporting, attributed to Wang Report: The campaign, called wfx-loot, targeted GitHub Actions, the automation used to build, test and publish software. Those jobs can hold credentials for the systems they deploy into. Aikido reported confirmed secret theft from at least 1,835 targets, although some targeted repositories never ran the payload.

Unverified reporting, attributed to Wang Report: Starting on November 10, the attacker used credentials from 4,837 compromised accounts to probe 61,764 repositories for write access. Pull requests titled “docs: dependency audit notes” accompanied the activity. The payload arrived through modified workflows, new workflows on short-lived branches or an installation hook.

Unverified reporting, attributed to Wang Report: For someone investigating an affected repository, the distinction between a probe and execution matters. Aikido identified the `wfx-docs` branch, the pull-request title and gaps in workflow run numbers as investigation clues. An open pull request alone does not establish that secrets were stolen.

Unverified reporting, attributed to Wang Report: What the automation could reach matters next. The script collected cloud credentials and supported exchanging GitHub identity tokens for temporary cloud sessions. Where permissions allowed, it could create long-lived credentials or change cloud identity and trust policies. The reporting describes those capabilities; it does not establish that every affected cloud account acquired persistent access.

Unverified reporting, attributed to Wang Report: Reverting the workflow would leave any credentials already created outside it untouched.

Unverified reporting, attributed to Wang Report: A separate report on N-able’s N-central remote-management platform shows another limit of checking the visible software state. Huntback reported 21 compromised production servers, including 19 running the latest Hotfix 2 release. The reported exploit required Legacy API access to be enabled. N-able urged customers to disable it while further remediation continued.

Unverified reporting, attributed to Wang Report: For N-central, the current version still left a feature setting to establish. For GitHub, the restored files still left an execution history and cloud permissions to account for. Neither report supports closing the investigation at the software check.
