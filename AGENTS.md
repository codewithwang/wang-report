# Personal-project agent instructions

## Owner standing authorization — 17 November 2026

For the owner's personal projects, complete authorized non-security software and operations work end to end without repeated owner-approval requests. This includes implementation, tests, fixes, PRs, merging, publishing, routine releases and **production deployment**. Personal-project production deployments are expressly **preapproved**. Older blanket instructions to stop for a separate merge or deployment approval are superseded for this scope. Make reasonable reversible decisions, complete the requested outcome, perform applicable automated/local checks, independently verify the result and repair failures. Missing optional GitHub CI or reviews alone does not require reapproval when local evidence is sound; required checks/reviews still apply. A merge is not proof of deployment, and deployment is not proof of live/device correctness.

**Security approval remains required.** Never bypass access controls, branch protections or platform-enforced prompts. Obtain applicable approval for security-sensitive work involving secrets, credentials, identity/access policy, security posture, network exposure, privacy/retention controls or confidential data transfer. Corporate/client environments and deployments are excluded from this personal-project authorization. It does not authorize unrelated purchases, contractual commitments, external messages, third-party sharing or irreversible loss of data.

Before modifying anything, inspect this project's README, existing instructions, accepted decisions, source-of-truth files and deployment/runbooks. Preserve originals, accepted architecture, design, user data and backups. Apply existing technical release checks and rollback provisions. Do not deploy merely because standing permission exists: deploy when it is a necessary step of the authorized task. If tools are unavailable or a protection blocks execution, report the exact blocker rather than treating saved authorization as executed work.
